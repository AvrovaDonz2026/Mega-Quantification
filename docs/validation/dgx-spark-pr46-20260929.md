# DGX Spark quantization validation — 2026-09-29

The complete Qwen3.8-27B checkpoint passed mixed W4A8 and uniform W4A4 calibration and HF export
on a single DGX Spark using PR #46 revision
`b91834f822ba6ea45806dbd6a5d0040878865782`. Vision and MTP quantization were
enabled. This verifies the quantization/export path; it is not a quality score
or a SGLang serving result.

The [machine-readable record](dgx-spark-pr46-20260929.json) includes both run
and audit summaries and SHA256 hashes of the locally retained evidence files.

- Every image checksum matched the dataset manifest and every image decoded.
- Runtime: `MEGAQUANT_LOW_MEMORY=1`,
  `MEGAQUANT_MAX_MEMORY=0:96GiB,cpu:24GiB`; local source/data mounts and
  offline Hugging Face access. Both `quantize_vision` and `quantize_mtp` were
  enabled, with `kv_cache: null` as declared by the Spark recipes.

The validation runner called the normal `megaquant` CLI and recorded timing,
PyTorch peak memory and shared-memory samples every three seconds. It did not
change the calibration or exporter. The equivalent quantization command was:

```bash
megaquant quantize -c recipes/qwen3.8-27b-nvfp4-w4a8.spark.yaml \
  --output /outputs/w4a8
megaquant quantize -c recipes/qwen3.8-27b-nvfp4-w4a4.spark.yaml \
  --output /outputs/w4a4
```

Use the mounts and image build procedure in the [Docker guide](../../docker/README.md#dgx-spark--gb10).

## Limits

No CUDA OOM occurred in either run. The tests cover the new OOM control flow,
including releasing failed frames and refusing an identical retry, but these
runs do not demonstrate recovery from a real GPU OOM. Loading briefly caused
shared-memory/swap pressure that receded before calibration; the explicit
Accelerate budgets are placement budgets, not hard process memory limits.

This does not test an installed FLA CUDA path, numerical accuracy, GPQA,
SGLang text/image generation, speculative MTP acceptance, or cross-node TP2.
The checksums identify calibration input; newly calibrated model bytes are
not claimed to match an earlier export.

The subsequent [2026-09-30 serving checks](dgx-spark-serving-20260930.md)
separately test text/image generation and embedded MTP draft acceptance.
