# MegaQuant v0.1.3

This patch release repairs NVFP4 calibration search and MTP calibration device
placement, and includes the completed DGX Spark GPQA evaluation and its strict
result checker.

## Changes

- Enable FP8 block-scale search for NVFP4 MSE and use static NVFP4 weight block
  scales for MSE and Local-Hessian so ModelOpt executes the requested search.
  Activation scales remain dynamic, with max calibration and NVFP4 group 16.
- Move precollected MTP calibration statistics with the branch to the target
  output device, preserving their values and avoiding CPU/CUDA mismatches.
- Add separate Spark MSE and Local-Hessian W4A4 recipes, with quantized vision
  and MTP, plus a GPU operator checker for actual search execution.
- Repair GPQA requests to send SGLang parameters at the correct JSON level
  and count final length finishes as wrong, retaining the chat-template token
  reserve.
- Accept repeated answer options from the official Diamond data; verify all
  198 unique dataset-matching records, predictions, summary and protocol before
  publishing a score.
- Add a dedicated Spark 262144-context, 16-request GPQA profile and completed
  evaluation reports. Package metadata and Spark image version labels are
  synchronized at 0.1.3.

## Recorded results

GPQA Diamond on one ARM64 GB10 DGX Spark, TP1, temperature 0, context 262144,
seed 0, shuffled choices, preserved xhigh thinking and speculative MTP disabled:

| Export | Correct / 198 | Accuracy | Length finishes | Unparsed |
|---|---:|---:|---:|---:|
| Mixed W4A8 baseline | 177 | 89.39% | 0 | 4 |
| Uniform W4A4 max baseline | 174 | 87.88% | 0 | 4 |
| Uniform W4A4 MSE | 178 | 89.90% | 3 | 4 |
| Uniform W4A4 Local-Hessian | 170 | 85.86% | 3 | 5 |

Every row is a formally checked complete 198-item result. For both new
candidates, all three length finishes are included among the unparsed responses;
the two columns must not be added. MSE improved this single score by four correct
answers over max; Local-Hessian scored four fewer. Both new candidates retain
very long outputs and length finishes. General quality recovery and recovery of
stopping behavior have not been established. The existing default is retained.

Both candidates completed full 27B PTQ and strict export audits, including
language, vision and MTP calibration. Fixed text/image/OCR checks passed with
and without embedded MTP; each candidate matched all 205 output token IDs
between those modes. These 32k functional checks do not establish broad vision
quality, 256k MTP quality or a speedup. The Python-response case checks nonempty
output, finite logprobs and token parity; generated code was not executed.

The new PTQ evidence is frozen at `14d5ad6f9d4ac30fc91a55b2ff4697f2ab90a76d`;
serving and evaluation are frozen at
`79b5dfef54618d0e385c5974d0ea508cd2fbdd40`. Those images report package version
0.1.2. They validate the repaired runtime before the 0.1.3 version and release
documentation changes; this release does not claim a fresh build or GPU rerun
of images carrying the 0.1.3 label. The earlier v0.1.2 container clean-build and
save/load evidence retains its own frozen revision and scope.

MSE resumed an interrupted run while preserving its 186-record prefix. Its
36,935.981-second recovery timer covers the 12 regenerated requests only; full
benchmark elapsed time is unavailable. Local-Hessian began from an empty
journal and recorded 68,875.212 seconds for its complete client run. These are
diagnostic timings, not a throughput comparison.

## Release assets

The GitHub release includes the wheel, source distribution, package-validation
record, aggregate candidate and baseline validation JSON, and `SHA256SUMS`.
The package assets are built from the release source; the validation JSON keeps
the actual frozen GPU revisions above. Model weights and container archives are
separate from these package assets. Build Spark images from this release
checkout using the runbook.
